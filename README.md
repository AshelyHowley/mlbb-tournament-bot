# MLBB Tournament Bot

Telegram-бот для регистрации и проведения турниров Mobile Legends.
`Telegram → бот (aiogram 3) → PostgreSQL`. PostgreSQL — единственный источник истины (Google Sheets не используется).

> Отдельный проект. Не связан с CourierBot: своя БД (`mlbb_tournament`), свой пользователь (`mlbb_bot`), своя папка.

## Возможности

* Регистрация **команды**: после названия создатель выбирает роль — капитан / участник (капитан другой) / только регистратор. Игроки вступают по player-ссылке, капитан — по отдельной captain-ссылке (максимум 5 человек **включая** капитана; регистратор-не-игрок в лимит не входит; идентификация по Telegram ID, username не нужен). Замена/удаление участников и передача капитанства — у капитана; выход участника. **Соло**-регистрация (роли EXP/GOLD/MID/JUNGLE/ROAM).
* Проверка подписки на канал и чат (`getChatMember`) перед сохранением; при ошибке Telegram регистрация **не** разрешается.
* «Моя регистрация», текстовая турнирная сетка (видна всем).
* Админ-панель (только `ADMIN_TELEGRAM_ID`): команды, соло, матчи, победитель, сетка, рассылка (текст/фото/видео), открытие/закрытие регистрации.
* Этапы хранятся в таблице `stages` — новый этап добавляется одной строкой `INSERT`, без правки кода.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполните **локально** `.env` (не вставляйте секреты в чаты и не коммитьте файл):

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_TELEGRAM_ID` | числовой Telegram ID единственного администратора |
| `DATABASE_URL` | `postgresql://mlbb_bot:PASSWORD@127.0.0.1:5432/mlbb_tournament` |
| `CHANNEL_ID`, `CHANNEL_URL`, `CHAT_ID`, `CHAT_URL` | уже заполнены значениями по умолчанию |
| `ACCESS_MODE` | `private` (только админ + `ALLOWED_USER_IDS`) или `public` (все). Другое значение — бот не запустится |
| `ALLOWED_USER_IDS` | Telegram ID обычных пользователей через запятую, например `6323637322,123456789` |

Значение по умолчанию в `.env.example` — `private` (безопасно). В боевом `.env` после релиза стоит `public`: бот открыт всем, подписка на канал и чат по-прежнему проверяется, админ-функции доступны только `ADMIN_TELEGRAM_ID`.

Доступ (`can_access_bot`) и права администратора (`is_bot_admin`) независимы: админ бота — только `ADMIN_TELEGRAM_ID`.
Пользователь из `ALLOWED_USER_IDS` — обычный участник, даже если он админ Telegram-чата. Чтобы открыть бота всем, поставьте `ACCESS_MODE=public` и перезапустите.

Обязательные условия в Telegram: бот должен быть **администратором** канала и чата (иначе `getChatMember` не работает и регистрация будет блокироваться).

### Права PostgreSQL

Пользователь `mlbb_bot` должен иметь право создавать таблицы в схеме `public` базы `mlbb_tournament`
(владелец БД имеет его в PostgreSQL 15+). Если миграция падает с `permission denied for schema public`, выполните под суперпользователем:

```sql
GRANT ALL ON SCHEMA public TO mlbb_bot;
```

## Запуск

```bash
python main.py
```

При старте: проверка конфигурации → подключение → `SELECT current_database(), current_user` (должно быть
`mlbb_tournament` / `mlbb_bot`, иначе аварийная остановка **до любых изменений**) → миграции → polling.
Только миграции: `python -m app.database.migrate`.

## Структура

```
main.py                  точка входа
app/config.py            загрузка/валидация .env (секреты не попадают в repr/логи)
app/database/            пул, проверка идентичности БД, раннер миграций, migrations/*.sql
app/repositories/        весь SQL (параметризованный)
app/services/            бизнес-логика без Telegram-кода (регистрация, админ, сетка, рассылка, подписка)
app/handlers/            aiogram-роутеры (start, registration, admin_*, fallback)
app/keyboards/           inline-клавиатуры
app/middlewares/         трекинг пользователей
app/utils/               нормализация/escape, логирование с редактированием секретов
tests/                   автотесты
```

## Инварианты, защищённые PostgreSQL

* уникальность названия команды (без учёта регистра/пробелов), капитана, соло-игрока (по Telegram ID);
* в команде не больше 5 участников (включая капитана): триггер блокирует строку команды и считает состав после блокировки; капитан всегда состоит в своей команде (проверка при COMMIT);
* один Telegram-пользователь — одна команда (`UNIQUE(user_id)`); токен приглашения уникален и имеет строгий формат;
* один человек не может быть одновременно соло и в команде (триггеры + advisory locks против гонок);
* матч: команды различны, победитель — только Team A/B, статус ⇔ наличие победителя, пара уникальна в рамках этапа;
* рассылка: `draft → sending` переводится атомарным `UPDATE … WHERE status='draft'` (повторное «Отправить» невозможно).

## Тесты

```bash
pip install -r requirements-dev.txt
set TEST_DATABASE_URL=postgresql://mlbb_bot:PASSWORD@127.0.0.1:5432/mlbb_tournament
python -m pytest -q
```

Тесты БД работают в **одноразовой схеме** `test_xxxxxxxx` (создаётся и удаляется автоматически), реальные данные турнира не затрагиваются.
Без `DATABASE_URL`/`TEST_DATABASE_URL` тесты БД пропускаются. Замеры нагрузки пишутся в `logs/perf_report.json`.

## Ручная проверка в Telegram (после заполнения .env)

См. чек-лист в `CHANGELOG.md`/финальном отчёте: регистрация команды и соло, подписка (вышел из чата → отказ),
закрытие регистрации, создание матча и выбор победителя, рассылка (предпросмотр → отправка, двойной клик), удаление с подтверждением.

## Ограничения

* FSM хранится в памяти процесса: при перезапуске незавершённые анкеты теряются (кнопки покажут «устарела»).
* Player-ссылка действует, пока в команде есть место и назначен капитан (ротации player-токена нет; captain-ссылку регистратор может обновить до назначения капитана). При закрытой регистрации новые вступления блокируются.
* Один экземпляр бота (long polling). Не запускайте две копии с одним токеном.

"# mlbb-tournamentKim-bot" 
"# mlbb-tournament-bot"
